# 网络读取失败与恢复

集成在单轮读取中进行有限重试。重试成功后发布本轮数据；重试耗尽或整轮超时后报告不可用，后续轮询继续尝试恢复。不会无限期保留旧数据来掩盖设备离线。

## 云端接入

- ecoMain 数据、ecoPlug 数据和状态、设备列表读取：首次发生暂时性连接错误、超时、响应传输不完整或 HTTP 502/503/504 时，等待 1 秒后重试一次。
- 重试仅针对失败接口；其他已成功的接口不会因这次网络重试而重复读取。ecoPlug 状态读取耗尽重试时，功率读取若成功，功率实体仍可用。
- HTTP 401/403 继续走已有认证恢复流程；其他业务错误、无效响应格式、TLS 证书错误及 HTTP 429 不做这类短重试。
- 单次状态请求超时为 15 秒，单次测量数据和设备列表请求超时为 20 秒。正常轮询间隔仍为 60 秒。
- 每轮运行期采集总时限为 45 秒，包含认证刷新和重试；配置流程中的设备列表读取不属于该轮询时限。
- 云端开关控制、登录请求不增加网络超时重试。控制请求的认证恢复行为保持不变。

ecoPlug 查询状态虽然使用 HTTP POST，但属于只读操作，因此明确允许重试；同一接口上的开关控制命令不适用。

## 本地 Modbus 接入

| 参数 | 值 |
| --- | --- |
| 连接及单次请求超时 | 2 秒 |
| 请求重试次数 | 1 次，即最多发送两次 |
| 自动重连初始等待 | 1 秒 |
| 自动重连退避等待上限 | 5 秒 |
| 正常轮询间隔 | 5 秒 |
| 整轮采集总时限 | 10 秒 |

请求重试与断线重连由 pymodbus 提供，不再叠加外层重试循环。已建立的连接断开后可自动重连；轮询发现连接未建立时，也会尝试连接。主动连接前会停止旧的后台重连，复用客户端，防止重复连接任务。

约 4 秒仅表示一个已连接请求在两次均无响应时的响应等待时间。整轮还可能包含连接、固件读取和多个寄存器块，因此单独设定 10 秒总时限。5 秒轮询间隔不是整轮执行时限。

本地相位设置使用 Modbus 功能码 06，写入确定的绝对值；底层在响应丢失时可能将同一值重发一次。应用层不额外重发写操作，收到成功响应后继续使用现有读回校验。写入超时仍会报告失败，不能据此断定设备未执行写入。

取消正在执行的 Modbus 读写会关闭连接并向上层传播取消信号；后续读取可以重新建立连接。整轮超时不发布半轮数据。

## 验证范围

在 HA 2025.9.0、2025.12.0、2026.3.0、2026.6.0、2026.9.4 官方依赖约束对应的环境中验证。测试仅使用模拟 HTTP 响应与本机回环 Modbus 服务，包含短暂失败恢复、持续失败、取消、重连和下一轮恢复场景。

这些参数尚未经过真实设备网络延迟测试；模拟测试结果不代表实网下不会出现不可用状态。
